## 零、部署架构原则（v2.3 新增）

> **NoteAI Pro 是面向全体线上用户的云端 SaaS 产品，所有推理、训练、存储均运行在云端基础设施上。**

| 维度 | 原则 |
|---|---|
| 推理服务 | 云端 API（Railway/Render/GCP），不在用户本地执行 |
| 模型存储 | 对象存储（S3/R2），不存 MacBook 本地磁盘 |
| 封面图存储 | 云端对象存储（S3/R2），按 domain 分桶 |
| 向量数据库（mem0） | Qdrant Cloud，不用本地 Chroma |
| 封面特征提取 | dots.mocr（云端 T4 GPU）+ dots.vlm1（云端 A100 集群） |
| 热词调度器 | 云端容器（Kubernetes CronJob 或 Railway Cron） |
| 本地环境用途 | **仅研发阶段节省成本用**，架构决策始终面向云端 |

## 二、总体可行性裁定

| 模块 | 可行性 | 核心风险 |
|---|---|---|
| 数据采集层 | **中等可行** | XHS 反爬是持续对抗，非一次性解决 |
| 模型训练层 | **高度可行** | 技术成熟，难点在训练数据质量而非算法 |
| 模型对用户的价值保障 | **有条件可行** | 需要验证闭环机制，无法做到"绝对"准确 |

## 三、模型核心定位升级（v2.0 重大更新）

### 3.1 从"内容评分"到"内容 × 市场契合度"

| 旧定位（v1.x） | 新定位（v2.0） |
|---|---|
| 回答「这篇内容质量如何？」 | 回答「这篇内容在当前时间点、当前市场环境下能跑多远？」 |
| 单维评分（内容质量） | 双维评分（内容质量 × 市场时机系数） |
| 特征35个（纯内容特征） | 特征43个（35内容特征 + 8市场时机特征） |

### 3.2 双维评分展示逻辑

```
最终评分 = 内容质量分（Content Score）× 市场时机系数（Market Timing）

用户界面展示：
  内容质量：72分  （赛道内 Top 28%）
  市场时机：0.89  （当前热词契合度高，发布窗口良好）
  综合评分：64分  （= 72 × 0.89）

两个维度分开展示，用户可以判断：
「内容已经好了，但时机不对，等热词窗口再发」
```

### 3.3 与千瓜/新红的本质区别

| | 千瓜数据 / 新红数据 | NoteAI Pro |
|---|---|---|
| 视角 | 回顾性：告诉你「上周哪些笔记爆了」 | 前瞻性：告诉你「你这篇发出去能跑多远」 |
| 行动指导 | 分析报告，用户自己决策 | 具体可操作建议：「把标题第3个词换成当前热词X，预测分提升N%」 |
| 护城河 | 数据广度 | 预测精准度 + 用户发布结果回流校准闭环 |

## 四、47个特征工程体系（v2.2 升级）

### 4.1 内容特征组（39个，v2.2 新增4个PLAD特征）

| 特征组 | 数量 | 核心特征 | 提取方式 |
|---|---|---|---|
| CES核心指标 | 5个 | comment_rate / save_rate / save_like_ratio / follow_conversion / early_ces_2h | 采集时计算 |
| 封面特征 | 8个 | 色温/饱和度/人脸数/情绪/食物/门店/文字贴片/9图 | 见第十五节拆分方案 |
| 标题特征 | 8个 | 正负情绪词/价格/疑问/新开信号/城市/数字/热词匹配 | 规则提取 <1ms |
| 内容实用性 | 7个 | 地址/营业时间/价格/交通/预约/必点/CTA引导 | 规则提取 <1ms |
| 标签策略 | 6个 | 标签数/POI标签/城市标签/大中小词梯度 | 规则提取 <1ms |
| 时间特征 | 4个 | 周末决策窗/午餐前/节假日前/距节假日天数 | 规则提取 <1ms |
| 格式特征 | 2个 | 图片数量/动态封面 | 规则提取 <1ms |
| **PLAD心理语言特征** | **4个** | **见下表** | **规则/统计计算** |

**PLAD新增4个特征（来源：RedNote-Vibe 论文 SHAP 分析，v2.2 新增）★**

| 特征名 | 含义 | 与CES的关联 | 提取方式 |
|---|---|---|---|
| word_freq_entropy | 词频熵：内容词汇多样性/信息密度 | **收藏率**最强预测因子 | jieba分词后计算香农熵 |
| phrasal_repetition | 短语重复密度：结构工整度 | **收藏率**强相关 | 滑动窗口n-gram重复率 |
| punctuation_ratio | 标点密度：情绪节奏感/可读性 | **点赞**和**评论**均强相关 | 字符统计 |
| interactive_stance | 互动导向：疑问句+CTA比例 | **评论率**最强预测因子 | 句尾问号+号召词检测 |

> 这4个特征提取成本接近零（纯规则/统计），但论文通过 SHAP 值验证其与互动数据的强相关性，直接补强 Model A 对收藏率和评论率的预测精度。

### 4.2 市场时机特征组（8个，v2.0 新增）★核心护城河

| 特征名 | 含义 | 数据来源 | 更新频率 |
|---|---|---|---|
| trend_momentum | 标题/标签命中热词的趋势斜率（上升/下降/平稳） | hot_keywords 表 | 每6小时 |
| trend_peak_distance | 距该热词搜索量峰值的天数（负数=未到峰，踩在峰前2天最优） | hot_keywords 表 | 每6小时 |
| category_saturation | 同品类本周新发笔记总数（越高竞争越激烈） | 品类统计聚合 | 每周日 |
| category_avg_ces | 同品类本周平均 CES 分（归一化基准线） | 品类统计聚合 | 每日 |
| keyword_search_vol | 主标签当前搜索量指数（1-100，来自搜索建议 API） | XHS 搜索建议 API | 每6小时 |
| keyword_competition | 同标签下存量笔记总数（搜索页竞争密度） | 标签聚合页计数 | 每周 |
| is_trending_topic | 是否命中平台当周推荐话题 | 发现页话题区 | 每天2次 |
| content_freshness | 该话题从首次出现至今天数（越小越处于红利期） | hot_keywords 历史记录 | 每6小时 |

## 五、三级爬取目标体系（v2.0 重构）

### 5.1 P1：热点感知（每60分钟，调度器A）— **已实现 v2.4**

| 爬取目标 | 入口 | 获取内容 | 驱动特征 | 状态 |
|---|---|---|---|---|
| XHS homefeed tag_list | /explore 8个品类 channel | 话题词频 → 相对热度指数 | keyword_search_vol / trend_momentum | ✅ |
| XHS 热搜 API（拦截） | hot_list/trending 接口 | 热搜词 Top50 + 趋势方向 | is_trending_topic | ✅ |
| 发现页话题区 | /explore 话题标签 | 平台推荐话题 + 话题下笔记数 | content_freshness | ✅ |

**实现文件**：`model/scheduler_a.py` + `model/hot_keywords.py`

**架构**：调度器内嵌 API 进程，启动时立即抓取，之后每 60 分钟循环。用户请求时直接读 `hot_keywords.db`（<5ms），命中热词注入 Claude prompt。

**市场时机系数**：`composite_score = ces_percentile × timing_coefficient`（0.6–1.4），已在 `/analyze` 响应中作为 `composite_score` 返回。

**剩余待补全**：`category_saturation`、`keyword_competition` 精确值需调度器B上线后计算。

### 5.2 P2：训练样本（每日01:00，调度器B）

| 爬取目标 | 采集方式 | 数量 | 样本类型 |
|---|---|---|---|
| 各品类笔记榜单 | 品类关键词搜索 → 按「最热」排序 Top200 | 8品类 × 200条 = 1,600条/天 | **高质量正样本** |
| 低互动笔记 | 品类关键词 → 按「最新」过滤7天+互动<50 | 8品类 × 75条 = 600条/天 | **关键负样本** |

> 正负样本设计是模型准确的基础——只喂爆款会导致模型无法识别失败原因。

### 5.3 P3：竞争环境（每周/每月）

| 爬取目标 | 频率 | 用途 |
|---|---|---|
| 品类主标签页周新增笔记数 | 每周日 | category_saturation 特征 |
| 达人分层账号池（1k/1w/10w/100w+） | 每月更新 | 训练集分层，剔除大号光环偏差 |
| 品牌合作笔记识别（「合作」标签） | 采集时实时过滤 | is_sponsored=true，不纳入基准训练 |

## 七、小红书反爬的真实壁垒（5层叠加）

### 第1层：网络指纹识别
- 检测：TLS 握手指纹 / HTTP/2 帧序 / Header 顺序
- 破解：Playwright（真实 Chromium）+ playwright-stealth
- 代价：每实例内存 200-300MB，资源较重

### 第2层：行为模式检测
- 检测：请求间隔规律性 / 滚动行为 / 鼠标轨迹
- 破解：随机 delay（2-8秒）+ 模拟滚动 + 随机停留
- **安全上限：10线程而非20线程**

### 第3层：API 签名验证（最难）
- 检测：X-Sign / shield / _pflag 等动态签名参数
- 推荐方案：Web 端爬取（无签名要求，内容基本够用）✅

### 第4层：账号风控
- 破解：50个账号池，需提前"养号"2周以上
- 现实约束：账号池准备期 2-3 周，不能立即用

### 第5层：IP 封禁
- 破解：住宅代理（Residential Proxy）
- 推荐服务商：Oxylabs / Brightdata / 国内 IPIDEA
- 月均代理成本：约 1,000-2,000 元

## 十、模型对用户价值的保障机制

### 10.1 模型的天然局限（必须正视）

| 局限 | 原因 | 缓解方案 |
|---|---|---|
| 选择性偏差 | 只能采集已发布笔记，失败笔记数据缺失 | 主动采集低互动笔记作为负样本（互动 <50） |
| 混淆变量 | 100万粉博主 vs 新号发同样内容，结果天壤之别 | 按粉丝量分层建模，不混用不同量级账号数据 |
| 平台黑箱 | XHS 真实分发权重未公开，CES 公式是行业推测 | 多指标交叉验证（7天互动 + 搜索曝光 + 收藏率） |

### 10.2 价值保障四道防线

**第一道：训练数据准入标准**
```
├── 笔记发布时间 ≥ 7 天（互动数据稳定）
├── 作者粉丝量 1,000-50万（排除头部账号光环效应）
├── 互动数据无异常（save/like > 0.1 排除刷量）
├── 正负样本各50%（高分+低分笔记均纳入）
└── is_sponsored=false（过滤品牌合作笔记）← v2.0 新增
```

**第二道：双维可解释性展示**
```
用户看到的不是"评分64分"
而是：
  内容质量：72分（封面偏低 → 建议加人脸元素）
  市场时机：0.89（当前「新开探店」热词上升期）
  → 「现在是发布好窗口，先改封面再发」
```

**第三道：真实发布数据回流校准**
```
Week 1：用户接受建议 → 修改 → 发布
Week 2：采集该笔记真实互动数据
Week 4：对比"采纳建议"vs"未采纳建议"用户组互动率差异
结果：若采纳建议组提升 <15% → 该特征权重有误 → 下次重训修正
```

**第四道：不确定性透明化**
```
✅ 正确做法：基于相似笔记，互动率区间 2.1%-4.8%
            当前特征与「爆款区间」的差距主要在封面和标签
子品类数据不足时（<200条）：
→ 主动告知用户「该细分品类数据不足，建议仅供参考」
```

## 十一、爬虫工具选型：MediaCrawler（v2.1 决策）

**决策：不购买千瓜/新红 API，全程自建爬虫。** 内容数据与热点数据均自采。

### 11.1 决策依据

| 维度 | 结论 |
|---|---|
| 市场时机数据（热词/热搜） | 千瓜/新红均不开放原始热词数据，**无论如何都必须自建** |
| 模型训练授权 | 第三方 API 使用协议通常禁止 AI 训练，需单独谈判且可能拒绝 |
| 数据控制权 | 外购数据存在断供风险，字段由对方定义 |
| 长期成本 | 全自建 12 个月累计 ~52,400 元，低于千瓜 API ~72,000 元 |

### 11.2 工具选型：MediaCrawler

**GitHub**: `NanmiCoder/MediaCrawler` | 48,692 stars | 2026-04-25 最近更新 | 持续维护

| 特性 | 说明 |
|---|---|
| 支持平台 | XHS、抖音、快手、B站、微博等，XHS 为主要目标 |
| 登录方式 | QR码 / 手机号 / Cookie 直供；**CDP 模式**可接管本地真实 Chrome |
| 反爬机制 | CDP 模式复用真实浏览器指纹，无需 JS 签名逆向，平台风控识别率低 |
| 代理支持 | 内置 IP 代理池配置（`config/base_config.py`） |
| 多账号池 | ❌ 开源版单账号；✅ 付费 MediaCrawlerPro 版内置多账号池 |
| 节省工期 | 替代自建 Playwright 框架，节省约 **2-3 周开发工期** |

### 11.3 MediaCrawler 不能解决的问题

> **养号仍然无法绕过。** MediaCrawler 解决的是「爬虫怎么写」，不是「如何避免账号风控」。新注册账号直接用于高频采集仍会触发封号。

账号策略调整（v2.1）：
- 开源版先用 **5-10 个账号**（非原计划50个），CDP 模式接管本地 Chrome 验证流程
- 中期如需扩量，评估 MediaCrawlerPro 付费版（多账号池已内置）或在开源版基础上自行扩展
- 养号周期 **14-21 天**，不可压缩，必须与爬虫开发并行进行

├── 计算 CES 标签（likes×1 + collections×1 + comments×4）
├── LightGBM 训练 Model A v0.1（内容质量分，无市场时机）
└── 目标：1-2周内跑出第一个可评估的模型

同步启动（不依赖上面完成）：
├── 调度器A开发上线（热点感知，无需账号，立即可跑）
├── 注册10个XHS账号，开始养号（14-21天不可压缩）

Week 3-4：本地生活专属数据补充

│   （补封面特征/标签特征/POI特征，RedNote-Vibe 无此字段）
├── dots.ocr 本地部署（有GPU时）或保留 Claude Haiku（无GPU时）

## 十三、最终判断建议（v2.2 更新）

| 问题 | 结论 |
|---|---|
| 冷启动需要多久？ | **1-2周**（RedNote-Vibe exploration_set 立即可训练 v0.1），原 7-8 周路径已过时 |
| Model A v1.0 需要多久？ | **5-6周**（RedNote-Vibe + MediaCrawler 本地生活补充 + 市场时机特征） |
| 买还是爬？ | **全自建**，不购买千瓜/新红 API |

| 特征数量？ | **47个**（原43个 + 4个 PLAD 心理语言特征） |
| 封面特征成本？ | dots.mocr 云端 T4（~$0.0004/张）+ dots.vlm1 A100 按需（~$0.02–0.05/张，仅 Pro 用户触发） |

> 千瓜/新红花了多年积累的是「分析数据」，NoteAI 要积累的是「预测能力」，两者不在同一赛道。

## 十五、封面评分方案：dots.mocr + dots.vlm1 云端架构（v2.3 全面升级）

**来源**：小红书官方 AI Lab（rednote-hilab）开源，MIT 许可证
**策略**：两层分工 + 成本分级，所有推理运行在云端 GPU 实例上

### 15.1 两模型分工

| 层级 | 模型 | 负责特征 | 云端算力 | 成本 | 覆盖用户 |
|---|---|---|---|---|---|
| 基础层 | **dots.mocr**（3B） | 封面文字内容、文字密度、版面布局类型、文字区域占比、可读性 | T4 GPU × 1 | ~$0.0004/张 | 全部用户 |
| 深度层 | **dots.vlm1**（~680B） | 色温配色、构图质量、人物情绪、美感评分、封面与正文一致性、品类视觉语言、情绪唤起强度 | A100 × 16+ | ~$0.02–0.05/张 | Pro 用户 / 按需 |

### 15.2 封面特征向量（14维，替换原8维）

| 特征名 | 来源 | 维度说明 |
|---|---|---|
| cover_has_text | dots.mocr | 有无文字覆盖（bool） |
| cover_text_density | dots.mocr | 文字像素占比（0–1） |
| cover_text_content | dots.mocr | OCR识别文字（用于语义分析） |
| cover_layout_type | dots.mocr | 版面类型：居中/三分/满版/对角线 |
| cover_text_readability | dots.mocr | 文字与背景对比度评分（0–1） |
| cover_text_layers | dots.mocr | 文字层数（单/双/多层） |
| cover_color_temp | dots.vlm1 | 色温：暖/冷/中性 |
| cover_saturation_level | dots.vlm1 | 饱和度风格：高饱和/莫兰迪/低饱和 |
| cover_has_face | dots.vlm1 | 有无人脸（bool） |
| cover_emotion_score | dots.vlm1 | 情绪唤起强度（0–1） |
| cover_composition_score | dots.vlm1 | 构图质量评分（0–1） |
| cover_aesthetic_score | dots.vlm1 | 视觉美感综合评分（0–1） |
| cover_category_match | dots.vlm1 | 封面与品类视觉符号匹配度（0–1） |
| cover_content_consistency | dots.vlm1 | 封面与正文内容一致性（0–1） |

### 15.3 云端部署架构

```
用户上传封面图
      │
      ▼
[基础层：dots.mocr，所有用户，同步返回]
  云端 T4 GPU 实例
  ├── 文字检测 + OCR
  ├── 版面分析
  └── → cover_text_* 6个特征向量
      │
      ▼（Pro 用户或离线批处理训练）
[深度层：dots.vlm1，Pro tier / 异步]
  云端 A100 × 16+ 实例（按需启动）
  ├── 视觉理解推理
  └── → cover_visual_* 8个特征向量
      │
      ▼
[特征拼接]
  cover_features(14维) + text_features(14维) + timing_features(8维)
  → LightGBM 推理（重训后版本）
  → 视觉表现力维度评分（当前 null → 有值）
```

### 15.4 分阶段实施策略（本地开发 → 云端生产）

#### 阶段一：本地开发阶段（当前）

> **目标**：以最低成本验证封面特征对 RMSE 的提升效果，完成全栈功能后再上云。

| 封面特征 | 本地开发方案 | 成本 |
|---|---|---|
| 文字密度/版面 | **dots.mocr 本地 CPU 推理**（慢但可用）或跳过，先用 PIL 估算 | 免费 |
| 色温/饱和度/亮度 | **PIL/OpenCV 规则计算** | 免费 |
| 人脸检测 | **InsightFace 轻量模型**（CPU可跑，2GB） | 免费 |
| 美感/构图/情绪/语义 | **Claude Haiku Vision API**（临时替代 dots.vlm1） | ~$0.002/张 |

**开发样本规模**：
```
下载10,000张（分层抽样，各domain按比例）≈ 2.5 GB 本地存储
Claude Haiku Vision 提取视觉特征：10,000 × $0.002 = $20（一次性）
训练 Model A v0.2：验证封面特征是否将 RMSE 从 14.45 压到 <12
特征提取完成后可删除原始图片，只保留特征向量（几 MB）
```

#### 阶段二：上云后替换（未来）

```
本地方案                    →  云端方案
PIL/OpenCV 色温计算         →  保留（轻量，继续使用）
InsightFace 人脸检测        →  保留（容器化部署）
Claude Haiku Vision         →  dots.mocr（T4）+ dots.vlm1（A100）
本地 data/covers/           →  S3/R2 迁移：rclone sync data/covers/ r2:noteai-covers/
```

**接口设计原则**：特征提取封装为统一函数 `extract_cover_features(image_path) → dict`，内部实现通过 `COVER_BACKEND=local|cloud` 环境变量切换，上云时改一行配置即可。

### 15.5 训练数据准备流程

```
Step 1: 分层下载10,000张封面图（本地开发）
  python model/download_covers.py --stratified 10000
  → data/covers/{note_id}.jpg  （约2.5 GB）

Step 2: 提取封面特征（本地开发方案）
  python model/extract_cover_features.py
  → PIL/OpenCV 色温/饱和度/亮度（6维）
  → InsightFace 人脸检测（1维）
  → Claude Haiku Vision 美感/构图/情绪（7维）
  → 输出 data/cover_features.parquet

Step 3: 合并特征 + 重训 LightGBM
  原28维特征 + 14维封面特征 = 42维
  Model A v0.2 目标 RMSE < 12

Step 4: 上云后用 dots.mocr + dots.vlm1 替换 Step 2
  全量91,517张 → 直接下载到 S3/R2
```

### 15.6 成本模型

```
本地开发阶段（一次性）：
  封面图下载：免费（XHS CDN 公开图片）
  Claude Haiku Vision（10,000张 × $0.002）≈ $20
  存储：~2.5 GB 本地磁盘

云端生产阶段（全量训练）：
  dots.mocr（T4）：91,517 × $0.0004 ≈ $37
  dots.vlm1（A100，Pro样本约10%）：9,152 × $0.03 ≈ $275
  S3/R2 存储（91,517张 × 250KB）：~22 GB，约 $0.50/月

在线推理阶段（日均1,000次评分）：
  dots.mocr：1,000 × $0.0004 = $0.40/天
  dots.vlm1（Pro用户20%触发）：200 × $0.03 = $6/天
```
