## 1. 商业首阶段容量合同

- 正式上线首阶段必须可靠受理 100 个同时提交的 AI 业务任务，任务可使用 Claude 或 Kimi；未来扩展目标为 1000 个同时 AI 任务。
- “同时使用”是指每个任务都能快速取得持久 `job_id`、安全排队、显示进度、断流恢复并得到可审计终态；不表示 100 个请求绕过背压同时直冲供应商。
- 100 个合成任务的首轮门禁：全部在 2 秒内被持久受理，0 丢失、0 重复 provider dispatch、0 重复扣费；Worker 重启、重复消息和短时数据库故障后仍可恢复。
- Claude 与 Kimi 的执行并发分别受真实账号 RPM、输入/输出 Token、余额、错误率和实测时延控制。增加 API Key 不增加组织或账号配额。

## 2. 已确认的生产边界

- 阿里云华南运行完整生产主系统：前端、用户 API、Admin、PostgreSQL、积分/支付、Kimi、AI Worker、对象存储、日志和监控。
- Render Singapore 只运行 Claude Gateway；浏览器不得直连 Gateway，Gateway 不连接业务数据库。
- PostgreSQL 是任务、账务和结果的唯一真相。V1先使用数据库任务队列；后续消息队列只传无内容 `job_id` 用于唤醒 Worker，不能取代数据库 claim/lease/fence。
- 不允许 Prompt、正文、图片、reasoning、Cookie、Token、Secret、完整 URL 或异常原文进入消息或普通日志。

## 3. 推荐生产地域与最小拓扑

推荐华南 1（深圳，`cn-shenzhen`）。正式购买前，在 ECS、ALB、RDS 和 Tair 购买页核对当日共同可售的两个可用区；优先从 ALB 支持且四类资源均有库存的两个可用区中选择，不提前把单区资源买死。

起步拓扑（所有付费规格均须先看购买页报价）：

- API：跨两个可用区各 1 个执行单元，建议每个 4 vCPU / 8 GB；伸缩目标 `min=2`，建议上限 `max=6`，上限需预算批准。
- AI Worker：跨两个可用区各 1 个执行单元，建议每个 4 vCPU / 8–16 GB；伸缩目标 `min=2`，建议上限 `max=12`，上限需预算批准。
- PostgreSQL：RDS PostgreSQL 16 高可用、跨可用区、4 vCPU / 16 GB 起、200 GB ESSD；上线前必须完成一次临时恢复演练。
- Tair：Redis 7 双副本、多可用区、2–4 GB，只做缓存、限流和短租约。
- 入口：公网 ALB 双可用区、HTTPS；API ECS 不绑定独立公网 IP。
- 出口：公网 NAT + 固定 EIP；API/Worker 通过统一出口访问 Render Gateway 和获准的外部服务。
- OSS：私有临时上传、模型制品、前端三个用途隔离；临时上传设置生命周期。
- 日志：SLS/CloudMonitor；仅采集固定错误码、计数、时延和资源指标。

## 5. 上线后监控和升级规则

NoteAI必须按 provider/model 独立采集：队列深度、最老任务年龄、排队/供应商/端到端 P50/P95/P99、Worker active lease、RPM、输入/输出 Token 配额、429/5xx/timeout、余额、费用和用量完整率。Sonnet 与 Haiku 的配额不能相加，Claude 与 Kimi 的配额也不能相互冒充。

- Warning：任一已知配额达到 70% 持续 5 分钟，或排队 P95 超过 30 秒持续 10 分钟。
- High：达到 85% 持续 3 分钟，或排队 P95 超过 60 秒、最老任务超过 120 秒。
- Critical：达到 95%、预测 15 分钟内耗尽、最老任务超过 300 秒，或出现丢任务/重复 provider/重复扣费。

在已批准的实例数和预算范围内，系统可自动增加 Worker、实施背压并保护费用门禁。超过已批准上限时，系统只创建升级建议并通知产品负责人；建议必须包含当前值、官方上限、增长率、预计耗尽时间、旧/新规格、费用影响、回滚方式和证据。未经再次批准，不自动提高 Claude/Kimi 消费上限，不购买更高云规格，也不通过减少 Agent、跳过评分或降低模型质量来掩盖容量问题。
